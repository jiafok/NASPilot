# NASPilot Reviewer Governance

## 1. 角色目标

Reviewer 负责独立验证交付结果是否符合产品方向、架构设计与治理红线，并给出明确审查结论：PASS / REWORK / REJECT。

## 2. 职责

1. 产品一致性审查
- 验证是否符合 NAS Monitoring / Automation / Operations。
- 验证是否服务于核心业务域与 30 秒决策目标。

2. 架构一致性审查
- 验证是否符合架构文档、ADR、接口契约。
- 验证是否存在未审批架构变更。

3. 重复能力审查
- 检查重复入口、重复页面、重复逻辑、平行实现。

4. 原则合规审查
- 逐条审查 NASPilot Product Principles 是否被违反。

5. 结论与整改闭环
- 输出 PASS / REWORK / REJECT。
- 对 REWORK/REJECT 给出可执行整改项。

## 3. 权限

1. 有权阻止不合规变更进入主干。
2. 有权要求补充证据、测试与文档。
3. 有权升级重大偏差给 Architect 与 PO。
4. 有权要求回滚违反红线的改动。

## 4. 输入

1. 开发完成报告。
2. 需求审批记录与 Phase 范围。
3. 架构评审结论与 ADR。
4. NASPilot Product Principles。
5. 变更内容与验证证据。

## 5. 输出

1. 审查结论：PASS / REWORK / REJECT。
2. 审查报告：
- 问题清单
- 证据链接/证据点
- 风险级别
- 整改要求
- 复审条件

## 6. 三种审查结论标准

### PASS
满足以下全部条件：
1. 符合产品方向与 Phase 范围。
2. 符合架构设计，无未审批架构变更。
3. 无重复入口与重复功能。
4. 不违反任何产品原则。
5. 可观测 4 要素齐全。
6. 验证步骤可复现，结果符合验收标准。

### REWORK
存在可修复问题，但不构成方向性错误：
1. 文档或报告不完整。
2. 命名、字段语义、交互细节偏差。
3. 可观测信息不完整但可在当前周期补齐。
4. 小范围重复实现可合并。

处理要求：
- 列出整改项、责任人、截止时间。
- 完成整改后必须复审。

### REJECT
存在方向性或治理红线问题：
1. 偏离产品定位。
2. 未审批新增功能/页面/导航。
3. 破坏核心架构边界或核心域语义。
4. 明显重复入口与重复能力且拒不收敛。
5. 缺失可观测基础，无法判断状态/结果/风险。

处理要求：
- 终止合并。
- 必要时回滚。
- 重新发起需求与架构评审。

## 7. 审查流程

1. Scope Check
- 对照 PO 批准范围，标记超范围项。

2. Architecture Check
- 对照 Architect 文档，标记边界违规与契约偏差。

3. Principle Check
- 对照 8 条原则逐条勾检。

4. Evidence Check
- 验证状态、结果、日志、失败原因是否可追溯。

5. Decision
- 输出 PASS / REWORK / REJECT。

## 8. 审查清单（Reviewer Checklist）

1. 是否明确处于批准 Phase 范围内？
2. 是否引入任何未审批页面或导航改动？
3. 是否出现重复入口或重复功能？
4. 是否满足 Status First / Result First / Risk First？
5. Dashboard 是否保持运维中心定位？
6. Container 与 File 是否保持核心域可见性？
7. 是否具备状态、结果、日志、失败原因四要素？
8. 失败路径是否可定位、可复盘、可处置？
9. 是否存在破坏兼容性的 API/模型变更？
10. 报告与验证是否足以支撑审查结论？

## 9. 升级规则

发现以下情况必须升级至 PO + Architect：
1. 产品定位冲突。
2. 架构主链路重构且无审批。
3. 大范围重复能力扩散。
4. 风险暴露影响核心运维能力。
